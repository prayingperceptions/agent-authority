# Contributing

The protocol is intentionally small. Prefer additions that improve interoperability, conformance, safety, or developer ergonomics without creating a hosted-service dependency.

Before proposing a new field, ask:

1. Is it part of identity, authority, delegation, enforcement, evidence, or lifecycle?
2. Can an existing standard already express it?
3. Can it be optional without creating incompatible implementations?
4. Does the field create authority accidentally?

Security-sensitive changes should include adversarial tests and a threat-model note.

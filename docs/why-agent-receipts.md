# Why Agent Receipts?

As software gains the ability to act through tools, a successful final answer is no longer enough to understand a run. Teams also need to know which tools were called, which authority rules were applied, whether an exceptional action was approved, and what artifacts were produced.

A receipt is a compact, portable record of observable execution facts. It is not a statement that an agent was “safe,” and a hash is not proof that the underlying data was truthful.

Agent Authority uses receipts as an evidence layer. The Contract grants authority, the Gate enforces it, and the receipt records the observable decision and execution result.

# Product Hunt Strategy

## Plausibility

Yes. Product Hunt currently lists Developer Tools and Open Source as active, growing launch categories, and explicitly says products should be usable so visitors can engage immediately. https://www.producthunt.com/p/general/product-hunt-s-state-of-tech-discovery-q2-2026

For this project, Product Hunt is more plausible after the GitHub launch produces a working public demo and a few real adopters.

## Phase 1 — ship on GitHub

Launch the developer preview on the personal `prayingperceptions/agent-authority` repository first.

Measure: clones/downloads, GitHub stars, issues, forks, real integrations, and Authority Score runs.

## Phase 2 — create a product surface

Add a simple landing page with:

- one-sentence pitch;
- 60-second interactive demo;
- Authority Score example;
- GitHub CTA;
- documentation;
- explicit developer-preview status.

## Phase 3 — Product Hunt

Use a personal maker account. Product Hunt says company accounts are not used for product posts, and you can hunt your own product. Do not pay anyone to hunt or manufacture votes. https://www.producthunt.com/launch/how-product-hunt-works

Schedule rather than rushing. Product Hunt currently supports draft/scheduled launches and recommends launching when prepared; there is no guaranteed golden day. https://www.producthunt.com/launch/preparing-for-launch

## Product Hunt headline

**Agent Authority — Give every AI agent a permission slip**

## Product Hunt subtitle

**Open-source identity, contracts, approvals, and policy enforcement for AI agents.**

## First comment

Show the concrete demo: Passport → Contract → Gate → allow/ask/deny → signed evidence. Then invite developers to break the delegation and approval boundaries.

## Goal

Do not optimize only for Product of the Day. Optimize for developers who install the project, create contracts, open issues, contribute adapters, or become design partners. Product Hunt itself emphasizes measurable goals beyond leaderboard position.
